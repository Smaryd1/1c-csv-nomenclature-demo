# Пример кода внешней обработки 1С: массовое изменение наименований

Небольшой демонстрационный пример на встроенном языке **1С:Предприятие 8.3**.

Задача: по списку `Код;НовоеНаименование` найти **существующие** элементы справочника `Номенклатура`, показать, что будет изменено, и обновить их только после подтверждения пользователя.

## Что реализовано

- Проверка структуры входных данных и обязательных полей.
- Выявление повторов кодов в исходном списке.
- Поиск номенклатуры по коду, разделение на «Изменить», «Без изменений», «Ошибка».
- Предварительный просмотр без записи в информационную базу.
- Защита от изменений между проверкой и записью: перед обновлением повторно читается текущий объект.
- Запись в одной транзакции: при ошибке запись всей пачки отменяется.

## Структура

- [`src/ObjectModule.bsl`](src/ObjectModule.bsl) — бизнес-логика обработки.
- [`src/FormModule.bsl`](src/FormModule.bsl) — команды управляемой формы.
- [`examples/sample.csv`](examples/sample.csv) — демонстрационные входные данные.

## Как собрать обработку в конфигураторе

1. Создать новую внешнюю обработку `.epf` и добавить управляемую форму.
2. В модуль объекта вставить содержимое `src/ObjectModule.bsl`.
3. На форме создать реквизит `ТекстДанных` типа `Строка` неограниченной длины и разместить многострочное поле ввода.
4. Создать реквизит `РезультатПроверки` типа `ТаблицаЗначений` с колонками:
   `НомерСтроки (Число)`, `Код (Строка)`, `СтароеНаименование (Строка)`,
   `НовоеНаименование (Строка)`, `Статус (Строка)`, `Комментарий (Строка)`.
   Разместить его таблицей на форме. Для ячеек результата отключить редактирование.
5. Создать команды `Проверить` и `Применить`, привязать одноимённые обработчики из `src/FormModule.bsl`.
6. Вставить код в модуль формы. Открыть обработку на **тестовой** базе с каталогом `Номенклатура`.
7. Вставить данные CSV в поле `ТекстДанных`, выполнить проверку, затем при необходимости применить изменения.

> Поставляется **исходный код, а не готовый EPF**. Запуск в конфигураторе и функциональное тестирование здесь не проводились. Перед использованием следует проверить совместимость с конкретным релизом 1С и настроенными правами.

## Формат входных данных

```csv
Код;НовоеНаименование
000000001;Болт М8 (оцинкованный)
000000002;Гайка М8
```

Ограничения демо:

- Разделитель `;`. Строки с кавычками CSV и `;` внутри наименования не поддерживаются и отклоняются. Текст помещается непосредственно в поле формы; это не обработка загрузки файла с диска.
- Используется типовой справочник `Номенклатура`, поиск выполняется по **уникальному строковому коду**. В конфигурациях с иной системой идентификации требуется адаптация.
- **Новые элементы не создаются**, дополнительные реквизиты не изменяются.
- Для большого объёма (десятки тысяч строк) нужны пакетный поиск и другая стратегия транзакций.

## Сценарии для ручной проверки

| Данные | Ожидаемый результат |
| --- | --- |
| Существующий код и новое имя | Статус «Изменить» |
| Существующий код и прежнее имя | Статус «Без изменений» |
| Несуществующий код | Статус «Ошибка»; запись блокируется |
| Повтор кода | Ошибка повторной строки; запись блокируется |
| Пустое имя или код | Ошибка; запись блокируется |
| Имя изменили в другой сессии после проверки | Ошибка перед записью; транзакция откатывается |
| Запись второй позиции завершилась ошибкой | Ни одна позиция из текущей пачки не должна измениться |

## Назначение

Учебно-демонстрационный пример кода обработки, подготовленный для публичного портфолио. Не содержит клиентских данных и фрагментов чужих информационных баз. Наличие этого репозитория само по себе не означает, что обработка прошла эксплуатационное тестирование.
